# Two-tier mapshaper globe — frozen snapshot

A working copy of `apps/places`'s globe renderer and data, taken at commit `0340b59` —
the last point before the app's globe is switched over to the `natural-earth-tiers`
three-tier approach. This exists purely as a fallback: if that switch doesn't work out, or
you want to compare the two side by side, this is the exact renderer/data pair that was
running before.

This is a snapshot, not an actively-developed prototype — it isn't meant to be built on
further. If you want to iterate on the two-tier approach itself, treat this as a starting
point for a new, separately-named directory rather than editing it in place.

## What's here

Verbatim copies (not modified beyond the final build-output step — see below):
- `webview-src/` — the app's globe renderer (`globe-entry.js` + `city-labels/`), copied from
  `apps/places/webview-src/`
- `scripts/data/*.json` — the four data files it depends on (`countries-coarse.json`,
  `countries-detail.json`, `admin1-provinces.json`, `cities.json`), copied from
  `apps/places/scripts/data/`
- `scripts/build.mjs` — the same merge/mesh/rewind/bbox/tiny-island pipeline as
  `apps/places/scripts/build-globe-html.mjs`, line for line. The only change: it writes a
  self-contained `dist/index.html` for standalone viewing in a browser, instead of wrapping
  the HTML as a committed `src/webview/globeHtml.ts` export for the RN WebView to consume.

`globe-entry.js`'s `ReactNativeWebView` bridge calls are already guarded
(`if (window.ReactNativeWebView)`), so it runs as a normal page here with no changes needed —
saved-place pins just won't appear, since nothing posts that data in without the RN host.

## Running

```
pnpm install
pnpm --filter two-tier-mapshaper build
open dist/index.html
```

`dist/` is gitignored and regenerated by the build.

## Restoring this into `apps/places`

If you switch to `natural-earth-tiers` and later want to revert:

1. Copy `webview-src/*` back over `apps/places/webview-src/*`
2. Copy `scripts/data/{countries-coarse,countries-detail,admin1-provinces,cities}.json` back
   over the same paths in `apps/places/scripts/data/`
3. Confirm `apps/places/scripts/build-globe-html.mjs` still matches this directory's
   `scripts/build.mjs` (modulo the dist-vs-.ts output step) — if it was edited after this
   snapshot was taken, the git history on commit `0340b59` is the more precise reference
4. `pnpm --filter @ley/places build:globe`, then fully relaunch the app (not just a Metro
   fast-refresh) to pick up the new WebView bundle
